# The reviewed dependency constraints for the MCP wheelhouse closure.
#
# Owner resolution 005 R005-03 Phase 1 requires the wheel closure to be resolved
# "against the repository's exact dependency lock or equivalent reviewed
# constraints", and explicitly rejects "an unpinned, time-varying closure from
# the index" as deterministic evidence. `uv.lock` covers the Platform tooling and
# names none of this closure, so these exact pins are that equivalent: reviewed,
# in-tree, and the only versions `scripts/check-package-builds.sh` will accept.
#
# The closure is `omnivia-core-mcp`'s declared `mcp>=2,<3` and its transitive
# requirements. The unmarked pins below are the common closure, resolved
# identically on macOS/arm64 and Linux/x86_64 at these versions. Windows
# resolves two additional packages the other platforms do not:
#
#   - `click` declares `Requires-Dist: colorama; platform_system == "Windows"`.
#   - `mcp` declares `Requires-Dist: pywin32>=311; sys_platform == "win32"`.
#     An evidence-based CPython 3.11 win_amd64 wheel resolution selected
#     `pywin32-312-cp311-cp311-win_amd64.whl`, so 312 is the reviewed pin.
#
# Both additions are pinned below with their exact declared marker rather
# than silently dropped, so the closure stays exact per platform. The wheels
# themselves still differ per platform, so hashes are recorded as run-time
# evidence by the gate rather than pinned here.
#
# Regenerate deliberately -- a drift is a dependency change somebody must review,
# and the gate fails until this file is updated to match:
#
#   python -m pip download --only-binary=:all: \
#     --platform manylinux2014_x86_64 --python-version 3.11 --abi cp311 \
#     --dest <tmp> "mcp>=2,<3"
#
# then rewrite the common pins below from the downloaded wheel filenames. Run
# the resolver under a Windows interpreter to confirm the marker-gated pin;
# pip's cross-target `--platform` option alone does not evaluate Windows markers.
